# Nimbus webhooks and event delivery

Webhook consumers should verify the signature, return a quick 2xx response, and process events asynchronously. Nimbus may retry a delivery when the endpoint times out or returns an error, so a consumer must be idempotent.

## Receiver checklist

1. Verify the signature against the raw request body before parsing it.
2. Store the event ID in a durable deduplication table.
3. Return a 2xx response quickly after accepting the event.
4. Process the event in a worker and retry transient failures with backoff.
5. Send permanent failures to a review queue rather than retrying forever.

Do not acknowledge an event before its ID is safely recorded. Do not process the same event twice merely because Nimbus delivered it again.

## Missing events

Check endpoint health, signature failures, response codes, and delivery logs. Use the event ID and delivery timestamp when asking support to investigate. Never include a webhook secret in the ticket.
