# Multi-factor authentication recovery

Use a saved recovery code or an existing authenticated session to update MFA. Recovery codes are single-use and should be stored offline in a secure place. Do not send MFA codes, recovery codes, QR images, or authenticator secrets in a ticket.

## Regaining access

If an authenticated session exists, open **Settings → Security → Multi-factor authentication**, verify the current factor, and enroll a new authenticator. If a recovery code is available, enter it on the sign-in challenge and immediately rotate the factor.

## Administrator verification

If neither a session nor a recovery code is available, an authorized workspace administrator must verify ownership before support can help. Support cannot disable MFA solely because an email address is claimed in a message. The transport sender and account records must be checked first.
